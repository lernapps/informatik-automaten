The crossing outside the school

A pedestrian crossing with a button is coming outside the school. The tech club of class 9b builds a model of it, controlled by a small computer. Jona, Selin and Mia are 14 now. Before they write any code, they chat in their group:

Selin: Plan first, code second. What do the lights have to remember? Jona: Which colour is on. Nothing else. Mia: And whether someone has pressed! The cars still have green then, but the lights already know. Selin: Then we design them as an automaton, like our juice machine back in year 6.

On this page you design an automaton yourself and test it. How to read a state diagram is on the page State diagrams.

Exercise

What are the inputs of the crossing?

  • Someone presses the button. right answer

    The button press comes from outside and happens in a moment. That is an input.

  • The time is up. right answer

    A small timer reports “time up”. For the automaton this is an input like the button.

  • The cars have green.

    That stays like this for a while. It is a state, not an input.

  • The WAIT light comes on.

    The lights do this themselves when someone presses. That is an output.

Four steps to an automaton

  1. Collect the inputs: what comes from outside? Here: the button and “time up”.
  2. Find the states: what does the automaton have to remember? Two situations that look the same can be two states: “cars green” and “cars green and someone waits”.
  3. Set the transitions: for every state and every input: where does it go? If nothing changes, the arrow goes back to the same state.
  4. Test: play input sequences and compare where the automaton ends with what the task says.

Outputs such as “WAIT light on” can be written at the transitions, as in chapter 1. Here you design only states and transitions.

complete

An automaton is complete when every state has an arrow for every input.

deterministic

An automaton is deterministic when every state has at most one arrow for every input. Then you always know where it jumps.

Design the crossing

Here you design class 9b's lights, without marks. Tick the cards that are states. Choose the start state. Then set the target of every row; the diagram draws itself. With “play” you see where a test sequence ends: ✓ means as asked, ✗ means somewhere else.

Pedestrian crossing outside the school. At the start the cars have green. Without a press of the button this stays so, even when the time is up. If someone presses the button, the cars keep driving until the time is up. Then amber comes for the cars, after the next time the green man, then red and amber for the cars and green again. During amber, the green man and red and amber, the button changes nothing.

  • button, time up → should be: cars amber
  • button, time up, time up → should be: green man
  • button, time up, time up, time up, time up → should be: cars green

There is no “Check” here: try things out freely.

The design of the crossing. State cards: cars green, cars green and someone waits, cars amber, green man, cars red and amber, press the button, WAIT light comes on. Inputs: button, time up. Test sequences:

  • time up, time up → cars green
  • button, time up → cars amber
  • button, time up, time up → green man

With JavaScript you choose the cards, the start state and the target of every row, and play the test sequences.

test sequence

A test sequence is a series of inputs with the state the automaton should be in afterwards.

Exercise

Jona says: “‘Cars green and someone waits’ looks just like ‘cars green’. One state is enough.” What happens if class 9b uses only one state?

  • The lights forget the button press or switch to amber without it. right answer

    At “time up” the lights must know whether someone pressed. They can only remember that in a state of their own.

  • Nothing, the lights are the same.

    The lights are the same, but what happens next is different. A state is what the automaton remembers, not what you see.

  • The lights show red for everyone.

    The task gives no reason for that. The problem is the missing memory of the button.

Two situations after which the same input leads to different things are two states, even if they look the same.
