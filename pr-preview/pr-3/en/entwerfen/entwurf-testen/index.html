Mia has designed the crossing. Jona tests her design and writes in the group chat:

Mia: I tested “time up, time up”. It ends at “cars green”, as it should. Done!

Jona: I played “button, time up, time up”. It should end at “green man”. It ends at “cars green”.

Selin: Then the people at the button wait forever.

Mia: Oh no. I only tested what happens without the button.

Mia's design of the crossing. Start at “cars green”. The arrows:

  • cars green – button → someone waiting
  • cars green – time up → cars green

  • cars amber – button → cars amber

  • green man – button → green man

Three kinds of mistakes

A design can be wrong in three ways.

1. An arrow is missing. The automaton is not complete: in one state it does not know what to do with one input. In turnstile A the arrow for “token” is missing at “open”.

Turnstile, design A. Start at “locked”. The arrows:

  • locked – token → open
  • locked – push → locked
  • open – push → locked

At “open” the arrow for “token” is missing.

2. Two arrows with the same input. In turnstile B two arrows with “token” leave “locked”: one to “open”, one back to “locked”. What should the automaton do? That is not deterministic.

Turnstile, design B. Start at “locked”. The arrows:

  • locked – token → open
  • locked – token → locked
  • locked – push → locked
  • open – token → open
  • open – push → locked

Two arrows with “token” leave “locked”.

deterministic

An automaton is deterministic when every state has at most one arrow for every input. In German it is also called “eindeutig” (unambiguous).

3. An arrow is wrong. The automaton is complete and deterministic, but does not do what the task wants. Only a test sequence that passes this arrow shows it, like Jona's sequence for Mia's lights.

If an automaton is complete and deterministic, every state has exactly one arrow for every input. So it has as many arrows as states times inputs. Good test sequences pass all of these arrows between them, not just the usual case.

Looking back

Mia has set the arrow “someone waiting – time up” to “cars amber”. Now her design passes all test sequences, and the tech club programs the lights from it. From class 6b's juice machine to class 9b's lights the same holds: an automaton remembers a state, and every input leads along an arrow to the next one. You can now design an automaton in four steps, check whether it is complete and deterministic, and test it with good test sequences.
